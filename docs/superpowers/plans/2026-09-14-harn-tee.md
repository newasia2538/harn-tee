# harn-tee Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the durable Thai bill-splitting product described in `docs/superpowers/specs/2026-09-14-harn-tee-design.md`.

**Architecture:** A Vinext/Next App Router client flow owns the editable form and responsive summary UI. Route handlers expose token-scoped bill CRUD, payment status updates, and QR upload/delete; D1 stores normalized bill data and R2 stores QR bytes. Calculation and validation live in pure modules so rounding and form behavior are independently testable.

**Tech Stack:** React 19, TypeScript, Vinext/Next App Router, Tailwind CSS 4, shadcn primitives, Drizzle ORM, Cloudflare D1/R2, Vitest.

**Spec:** `docs/superpowers/specs/2026-09-14-harn-tee-design.md`

## Global Constraints

- Thai UI, mobile-first, friendly food-bill visual language.
- No user accounts or login; bearer edit/share tokens are opaque and unguessable.
- D1 is the source of truth for bills; R2 stores QR image bytes.
- VAT and service charge both use the item subtotal only.
- Money is displayed to two decimals; participant final amounts round up to two decimals.
- Public share access is unlisted; edit link is admin access and must be warned about.
- Do not modify `components/ui` vendored primitives or add a new UI library.
